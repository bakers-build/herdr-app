# Conventions

How this repository builds and checks its mods, and where that follows Herdr.

Reference: [herdrdev/herdr-app](https://github.com/herdrdev/herdr-app) at tag `v0.1.15`
(commit `9950887`). The layout examples in `herdrdev/herdr-layout-examples` show the same mod
format.

| Item | Herdr | herdr-app | Adopted / Deviation | Reason |
|---|---|---|---|---|
| Mod format | Plain ES-module JavaScript, `mods/<name>/main.js` + `mod.json`, imports from `gpui-kit`, `gpui-base` and `herdr`; no build | The same, starting with the placeholder `mods/bakers/` | Adopted | Herdr loads mods as they are, so mods need no build or TypeScript. |
| Runtime version | Bun, pinned to `1.4.4` in CI | Bun `1.4.4`, pinned in `package.json` (`packageManager`, `engines`) and in CI; `bun.lock` committed | Adopted | Same runtime as Herdr's own scripts and tests. |
| Tests | `bun test` over `scripts/*.test.ts`; each test reads a mod's `main.js`, strips the imports, evaluates it with `new Function` over stubbed globals and asserts on the element tree | `bun test` over `tests/*.test.ts`, the same pattern (`tests/bakers.test.ts`) | Adopted | Tests a mod's real source without a Herdr window or core. |
| Coverage | None | `bun run test` runs `bun test --coverage` (lcov report, `tests/**` not counted), then `bun run coverage`, which fails when the repo-wide lines or functions coverage falls below the floor in `scripts/check/coverage.ts` (92 % lines, 90 % functions: the HERDRAPP-4 baseline rounded down) | Deviation | Bun's `coverageThreshold` holds every file to the floor on its own, so one untested file would fail the run; the floor is meant for the whole repo. Raise it as coverage grows. |
| Contract test | None | `bun run test:contract` and the CI job `contract`: `tests/contract/run.ts` starts `ghcr.io/bakers-build/bakers-build/php:0.11.0` (pinned by digest, public) with SQLite instead of MariaDB (`tests/contract/settings.sqlite.php` replaces the image's `settings.container.php`; the config copy adds the `sqlite` module), installs from `config/sync`, seeds the server's own `scripts/e2e/seed-test-world.sh`, creates an API key for `fixture-agent` (`tests/contract/key.php`) and runs `tests/contract/*.test.ts`; the test gets its token at `/oauth/token` (client credentials), as `bakers auth token` does. A plain `bun test` skips it | Deviation | The unit tests run against a stubbed JSON:API server, which cannot show what the real one accepts: it applies a boolean filter as `1`/`0` and silently matches nothing for `"true"`/`"false"`. Update the image pin when the server changes its JSON:API. |
| Herdr check | `herdr-app check <mod>` loads the mod and materializes its eager native elements in a hidden window | `bun run herdr-check` and the CI job `herdr-check` (`ubuntu-24.04`, `xvfb-run`, Mesa's software Vulkan): `scripts/check/herdr-check.ts` uses `HERDR_APP` or an installed `herdr-app`, else downloads the pinned Linux build from `releases.herdr.dev` and checks its SHA-256 from `types/herdr-version.json` | Adopted | Herdr publishes its builds on `releases.herdr.dev` (`app/<version>/manifest.json`), not as GitHub releases. Not part of `bun run check`: it needs Herdr installed or a download. When raising the Herdr pin, copy the new checksums from that version's `manifest.json`. |
| E2E test | None | `bun run test:e2e` and the CI job `e2e` (Linux, under `xvfb-run`): `tests/e2e/run.ts` starts the seeded server as the contract test does (`tests/server/bakers-server.ts`, container `herdr-e2e`, port 18081), signs the real bakers CLI `0.11.0` in with the seed's API key (`bakers config init --auth-type client_credentials`, `bakers auth login`), starts Herdr with `HOME`, `HERDR_APP_HOME` and `BAKERS_HOME` in a temp directory (under `/tmp` on macOS: socket paths), installs the mod with `scripts/install.ts` and runs `tests/e2e/*.e2e.test.ts`. The test drives the window with `herdr-app do` and observes `ls`, `status` and the window's `shared.json`, no pixels. Locally on macOS a real, isolated window opens. A plain `bun test` skips it | Deviation | Unit tests stub Herdr and the server, the contract test stubs Herdr; only this run shows that the mod, installed as a developer installs it, loads real tickets in the real window. The isolated `HOME` keeps the developer's herdr-core, its remote machines and the CLI's session store (`~/.config/dropsh`) out of the run. |
| Type check | Herdr writes a `jsconfig.json` beside mods: `target`/`module` `ES2022`, `moduleResolution` `bundler`, `lib` `ES2022`, `checkJs`, `strict`, `strictNullChecks: false`, `noEmit` | `tsc -p jsconfig.json` (`bun run typecheck`) with the same options except `strictNullChecks: true`, a root `jsconfig.json`, `paths` to the vendored `herdr` types, and `@types/bun` for the tests; TypeScript `7.0.2` accepts every option, so no older version is needed | Deviation (`strictNullChecks`) | The HERDRAPP-3 review found `undefined` bugs that only a null-aware check reports. Fields that `init` sets are declared as class fields with JSDoc types; inside a `.when(cond, branch)` the branch uses an unreachable fallback (`?? 0`, `?? ""`) because narrowing does not reach into the closure. |
| Implicit any | Herdr's jsconfig has `strict` (so `noImplicitAny`), yet its shipped mods use untyped parameters throughout (for example `find(node, id)` in `tabs`) | `noImplicitAny: true`: every parameter the real types cannot infer carries a JSDoc type (`cx` is `import("gpui-kit").Context`, `AsyncContext` in `init`) | Adopted | The vendored gpui-kit types give callbacks their parameter types, so only method and helper parameters need JSDoc. |
| Vendored types | `herdr.d.ts` ships in `defaults/`; `gpui-kit.d.ts` (which declares `gpui-kit`, `gpui-base` and the other built-in modules) is generated at runtime from Herdr's component and style registries | `types/gpui-kit.d.ts` and `types/herdr.d.ts` are copies of `~/.config/herdr-app/` from an installed Herdr, each with a `// Vendored from herdr-app <version>` first line (licence in `types/LICENSE-herdr`). `types/herdr-version.json` pins the Herdr and gpui-shell versions; `bun run herdr-types` (part of `check`) fails when a header differs from the pin and, where `herdr-app` is installed, when the installed version differs. To refresh: copy both files, restore the first line with the new version, update the pin, run `bun run check` | Deviation (generated copy) | The real types catch what the old shim could not (for example a theme color passed as a plain string where gpui-kit takes a `#rrggbb` `Color`). `ui/theme.js` `tokens()` bridges `herdr.theme()`'s `Record<string, string>` to that `Color`. |
| Lint / format | None for JavaScript (Rust only) | Biome `2.6.7` with the recommended preset, plus errors for unused imports and variables, floating promises (nursery `noFloatingPromises`) and `console` in `mods/` (scripts and tests may log): `bun run lint`, `bun run format:check`, `bun run format`. `types/`, `.bakers/` and Markdown are excluded | Deviation | The repository requires lint and format checks. One tool does both, with a single dev dependency, and it runs fast under Bun. |
| Workflow lint | None | The CI step `Actionlint` runs `rhysd/actionlint` `1.7.12`, pinned by image digest, over `.github/workflows` (with shellcheck); `bun run lint:ci` runs the same image locally (Docker, e.g. OrbStack) | Deviation | The HERDRAPP-3 review asked for it; an image pinned by digest needs no download script, and Docker is preinstalled on ubuntu runners. |
| Editor config | None | `.editorconfig`: UTF-8, LF, final newline, trimmed whitespace, 2-space indent, matching Biome | Deviation | Herdr has none; this keeps editors in line with the formatter. |
| Task runner | `justfile` (`just test`, `just check`) | `justfile` with `test` and `check` recipes, which call the `bun run` scripts | Adopted | Same entry points as Herdr. CI calls the scripts directly, so `just` is optional. |
| CI triggers | `push` to `master` and every `pull_request` | `push` on every branch and every `pull_request` | Deviation | Every push is checked, as this repository requires. A branch with an open PR runs twice (push and PR). |
| CI jobs / check name | A per-platform test matrix plus an aggregate check named `test`; job `timeout-minutes` | A single Linux job named `test` (install, lint, format check, type check, test), `timeout-minutes: 10` | Adopted (check name, timeouts); Deviation (no matrix) | The mods are plain JavaScript with no native code, so one platform is enough. |
| CI permissions and pinning | `permissions: contents: read`; actions pinned to commit SHAs with a version comment; `persist-credentials: false`; `concurrency` cancels older runs per PR or ref | The same, with the same `actions/checkout` and `actions/cache` pins | Adopted | Herdr's org rules for supply-chain safety. |
| Caching | `actions/cache/restore` + `save`; only pushes to the default branch save; keys carry the pinned toolchain version | `~/.bun/install/cache`, keyed on Bun version and `bun.lock`; only pushes to `main` save | Adopted | PR caches can't evict the one everybody restores. `bun install --frozen-lockfile` runs after the restore, so a stale cache only slows a run. |
| Dependency updates | Dependabot for `github-actions`, monthly, grouped | The same file, verbatim | Adopted | Keeps the commit-pinned actions current. |
| Versioning | No releases or tags; Herdr records a mod's `version` when it clones one | SemVer tags `v<x.y.z>` computed from Conventional Commits since the last stable tag (`bun run release:version`); `-next.<n>` pre-releases from `next`. `mods/bakers/mod.json` carries `0.0.0-dev`; only the packaged copy is stamped | Deviation | Releases work as in bakers-build, and the repo never needs a version-bump commit, so `main` merges the frozen `next` SHA unchanged. |
| Release artifact | Mods are cloned from a git repo | A GitHub release per version with `herdr-bakers-<version>.zip`: `mods/bakers`, `scripts/install.ts`, `scripts/layout.js`, `README.md`, created by the CI job `release` | Deviation | A mod is a plain folder, not an npm package; the ZIP installs without a checkout or `bun install`. |
| PR titles | No rule | Conventional Commits (`type(scope)!: subject`), enforced by the CI job `pr-title`; the title reaches the check only through `env` | Deviation | The squash into `next` makes the title the commit that decides the version bump. |
| Branch model | `master` only | `next` integrates (squash, feature tickets branch from it), `main` releases (merge commits from release branches only); dependabot targets `next` | Deviation | The same flow as bakers-build: deployment tickets freeze `next` and merge it into `main`. |
